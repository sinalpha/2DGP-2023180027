# PRD: 소닉 애니메이션 뷰어

## 1. 목표

`sonic-sprite.png`에 들어있는 모든 동작 애니메이션을 차례대로 재생해서 보여주는 뷰어를 만든다.
사용자는 아무것도 조작하지 않고 보기만 한다. (종료 입력만 받는다.)

## 2. 개발 환경

| 항목              | 내용                                                          |
| ----------------- | ------------------------------------------------------------- |
| 언어 / 라이브러리 | Python, pico2d                                                |
| 소스 파일         | `sonic_animation_viewer.py` (단일 파일)                     |
| 이미지            | `sonic-sprite.png` (399 x 525 픽셀, 배경 투명)              |
| 위치              | `Labs/LEC09/`                                               |
| 실행              | `Labs/LEC09/` 폴더에서 `python sonic_animation_viewer.py` |

## 3. 동작 방식

1. 첫 번째 동작 애니메이션을 **5번 반복** 재생한다.
2. **1초 쉰다.** 쉬는 동안에는 그 동작의 마지막 프레임을 그대로 보여준다.
3. 다음 동작 애니메이션으로 넘어가서 1~2를 반복한다.
4. 마지막 동작까지 끝나면 첫 번째 동작으로 돌아가 **무한 반복**한다.

```
동작 1 x5 → 1초 쉼 → 동작 2 x5 → 1초 쉼 → ... → 동작 10 x5 → 1초 쉼 → 동작 1 x5 → ...
```

## 5. 스프라이트 시트 분석

### 5.1 구조

- 시트는 칸 크기가 일정하지 않다. 그래서 프레임 위치를 **직접 적어야** 한다.
- 가로로 한 줄이 한 동작이다. 동작은 모두 **10개**, 프레임은 모두 **76개**다.
- 맨 위 제목 글자(y 1~32)와 맨 아래 제작자 표기·다른 캐릭터(y 472~524)는 재생하지 않는다.

### 5.2 좌표 규칙

프레임 하나는 `(x, 너비, 좌우 보정값)`, 동작 하나는 `(아래쪽 y, 높이, 프레임 목록)`으로 적는다.

**위아래 흔들림 막기** — 같은 줄에 있는 프레임은 아래쪽 y와 높이를 줄 전체 값으로 똑같이 쓴다.
한 동작 안에서 프레임 높이가 모두 같아지므로 발 위치가 위아래로 흔들리지 않는다.

**좌우 흔들림 막기** — 프레임마다 너비가 다른데 모두 화면 가운데를 중심으로 그리면, 너비가 바뀔 때 몸통이 좌우로 밀려 보인다.
(예: 동작 7은 너비가 29에서 39로 바뀐다.) 그래서 프레임마다 **좌우 보정값**을 둔다.

- 보정값은 원본 픽셀 단위다. 그릴 때 `보정값 x 배율`만큼 x 위치를 옮긴다.
- 양수면 오른쪽으로, 음수면 왼쪽으로 옮긴다.
- 처음에는 모두 0으로 넣고, 실행해서 몸통이 밀려 보이는 프레임만 값을 고친다.

pico2d는 y좌표가 **아래에서 위로** 증가한다. 그림 편집기에서 본 좌표(위에서 아래로)는 이렇게 바꾼다.

```
pico2d 아래쪽 y = 525 - (편집기에서 본 줄의 아래쪽 끝 y + 1)
```

### 5.4 확인이 필요한 부분

- **동작 1의 3~4번째, 7~9번째 프레임**은 시트에서 서로 붙어 있어서 경계를 어림으로 나눴다. 실행해서 옆 프레임이 살짝 끼어 보이면 x와 너비를 1~2픽셀씩 고친다.
- **좌우 보정값**은 눈으로 보고 정해야 한다. 너비 차이가 큰 동작 2, 7, 8부터 확인한다.
- 한 줄에 서로 다른 동작이 섞여 있을 수 있다. (예: 동작 8은 앞 6프레임과 뒤 2프레임의 모양이 다르다.) 실행해 보고 어색하면 동작을 둘로 나눈다. 나누면 동작 개수가 늘어난다.

## 6. 프로그램 설계

### 6.1 상수

| 이름                                | 값       | 뜻                              |
| ----------------------------------- | -------- | ------------------------------- |
| `CANVAS_WIDTH`, `CANVAS_HEIGHT` | 800, 600 | 창 크기                         |
| `SCALE`                           | 6        | 확대 배율                       |
| `FRAME_TIME`                      | 0.1      | 프레임 하나를 보여주는 시간(초) |
| `REPEAT_COUNT`                    | 5        | 동작 하나를 반복하는 횟수       |
| `REST_TIME`                       | 1.0      | 동작 사이에 쉬는 시간(초)       |
| `ACTIONS`                         | 5.3의 표 | 동작 목록                       |

`ACTIONS`의 모양:

```python
ACTIONS = [
    (447, 39, [(1, 29, 0), (31, 26, 0), ...]),   # 동작 1
    (407, 39, [(8, 26, 0), (37, 27, 0), ...]),   # 동작 2
    ...
]
```

### 6.2 상태 변수

| 이름             | 뜻                                              |
| ---------------- | ----------------------------------------------- |
| `running`      | 프로그램을 계속 돌릴지 여부                     |
| `action_index` | 지금 재생 중인 동작 번호                        |
| `frame_index`  | 지금 보여주는 프레임 번호                       |
| `repeat`       | 지금 동작을 몇 번 끝냈는지                      |
| `resting`      | 쉬는 중인지 여부                                |
| `last_time`    | 마지막으로 프레임을 넘긴(또는 쉬기 시작한) 시각 |

### 6.3 함수

| 함수                | 하는 일                                                    |
| ------------------- | ---------------------------------------------------------- |
| `handle_events()` | 창 닫기, ESC 입력을 받으면`running`을 `False`로 바꾼다 |
| `update()`        | 시간이 됐으면 프레임을 넘기거나, 쉬기를 시작하거나 끝낸다  |
| `draw()`          | 지금 프레임을 화면 가운데에 확대해서 그린다                |

### 6.4 메인 루프

```
창 열기 → 이미지 불러오기
running인 동안 반복:
    handle_events()
    update()
    draw()
    delay(0.01)
창 닫기
```

### 6.5 update 규칙

시간은 `get_time()`으로 잰다. `delay(1.0)`으로 통째로 멈추지 않는다. (쉬는 동안에도 ESC가 바로 먹어야 하기 때문이다.)

**재생 중일 때** — `FRAME_TIME`이 지났으면:

1. `frame_index`를 1 늘린다.
2. 마지막 프레임을 넘어갔으면 `repeat`를 1 늘린다.
   - `repeat`가 `REPEAT_COUNT`보다 작으면 `frame_index`를 0으로 돌린다.
   - `REPEAT_COUNT`가 됐으면 `frame_index`를 마지막 프레임에 두고 쉬기를 시작한다.

**쉬는 중일 때** — `REST_TIME`이 지났으면:

1. `action_index`를 1 늘린다. 마지막 동작을 넘어갔으면 0으로 돌린다.
2. `frame_index`와 `repeat`를 0으로 돌리고 재생을 다시 시작한다.

### 6.6 draw 규칙

지금 동작의 `(아래쪽 y, 높이)`와 지금 프레임의 `(x, 너비, 좌우 보정값)`으로 그린다.

```python
image.clip_draw(x, bottom, w, h, 400 + dx * SCALE, 300, w * SCALE, h * SCALE)
```

## 7. 종료

- 창 닫기 버튼(`SDL_QUIT`) 또는 ESC 키(`SDL_KEYDOWN` + `SDLK_ESCAPE`)를 누르면 종료한다.
- 재생 중이든 쉬는 중이든 바로 종료돼야 한다.
- 루프를 빠져나온 뒤 `close_canvas()`를 호출한다.

## 8. 개발 단계

한꺼번에 작성하지 않고 아래 단계별로 만들면서 **단계마다 커밋**한다.

### 8.1 규칙

- 개발 단계는 **20단계 이상**으로 나눈다. (지금은 27단계)
- 한 단계가 끝나면 커밋을 하나 한다. 그래서 커밋도 20개 이상이 된다.
- 커밋 메시지는 **반드시 한글로** 쓴다.
- 커밋 메시지는 `DRILL #N. 스텝NN 내용` 형식으로 쓴다. (예: `DRILL #N. 스텝01 창 열고 닫기`)
- 단계마다 실행해서 "확인할 것"이 보이면 다음으로 넘어간다.
- 단계를 합치거나 나누더라도 20단계 아래로 줄이지 않는다.
